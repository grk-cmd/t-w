## 1. VS Code 준비하기

**VS Code**(Visual Studio Code)는 무료 편집 프로그램입니다. 한 화면에서 **파일 목록, 문서 편집, 터미널, git, Claude** 를 모두 쓸 수 있어서 비개발자에게 가장 편합니다.

> 개발자는 IntelliJ 같은 다른 도구를 쓰기도 하지만, 이 문서는 VS Code만 설명합니다.

### 1.1 설치

1. https://code.visualstudio.com 에 들어갑니다.
2. **Download** 버튼으로 받습니다. (맥은 `.zip` → 압축을 풀고 `Visual Studio Code` 를 **응용 프로그램(Applications)** 폴더로 끌어다 놓기)
3. 실행합니다. 맥에서 "인터넷에서 다운로드한 앱" 경고가 뜨면 **열기** 를 누르세요.

### 1.2 화면을 한국어로 바꾸기

1. 왼쪽 세로 막대에서 **확장(Extensions)** 아이콘(네모 4개 모양)을 누릅니다. 단축키 `⌘⇧X` (Windows `Ctrl+Shift+X`)
2. 검색창에 `Korean` 입력 → **Korean Language Pack for Visual Studio Code** (Microsoft) → **Install**
3. 오른쪽 아래에 "언어를 바꾸고 다시 시작할까요?" 알림이 뜨면 **Change Language and Restart** 를 누릅니다.
4. 알림이 안 뜨면: `⌘⇧P` (Windows `Ctrl+Shift+P`) → `Configure Display Language` 입력 → `한국어(ko)` 선택 → 재시작

> `⌘⇧P` 로 여는 창을 **명령 팔레트** 라고 합니다. 메뉴를 못 찾겠으면 여기에 이름을 치면 거의 다 나옵니다.

### 1.3 VS Code 화면 구성

| 위치 | 이름 | 하는 일 |
|---|---|---|
| 맨 왼쪽 세로 막대 | **작업 막대** | 탐색기, 검색, 소스 제어(git), 확장 등으로 바꾸는 아이콘들 |
| 왼쪽 패널 | **탐색기** | 프로젝트의 폴더와 파일 목록 (`⌘⇧E`) |
| 가운데 | **편집기** | 파일 내용을 보고 고치는 곳 |
| 아래쪽 | **터미널** | 명령어를 입력하는 곳 (`⌃``, 아래 1.5) |
| 맨 아래 파란 줄 | **상태 표시줄** | 지금 브랜치 이름(`main`), 동기화 버튼 등이 보임 |

### 1.4 프로젝트 폴더 열기

- 메뉴 **파일 → 폴더 열기…** → 프로젝트 폴더(예: `문서/t-w`)를 고르고 **열기**
- "이 폴더의 작성자를 신뢰합니까?" 라고 물으면 **예, 작성자를 신뢰합니다** 를 누릅니다. (우리 팀 저장소이므로)
- 왼쪽 탐색기에 `app`, `checks`, `docs`, `package.json` 등이 보이면 제대로 연 것입니다.

> **중요**: 항상 **프로젝트 폴더 자체**(`t-w`)를 여세요. 그 위 폴더(`문서`)나 그 안의 하위 폴더(`docs`)를 열면 git과 Claude가 제대로 동작하지 않습니다.

### 1.5 VS Code 안에서 터미널 열기

- 메뉴 **보기 → 터미널**
- 단축키 **`` ⌃` ``** (맥: Control + 백틱) / Windows **`` Ctrl+` ``**
  - 백틱(`` ` ``)은 키보드 왼쪽 위, 숫자 `1` 왼쪽에 있는 키입니다.
- 화면 아래에 터미널이 열리고, **프로젝트 폴더에서 자동으로 시작**합니다.

### 1.6 추천 확장 프로그램

확장(`⌘⇧X`)에서 이름으로 검색해 설치하세요.

| 확장 | 필수? | 하는 일 |
|---|---|---|
| **Korean Language Pack** (Microsoft) | 필수 | 화면 한국어 |
| **Claude Code** (Anthropic 공식 확장) | 필수 | VS Code 안에서 Claude와 대화 ([4장](#4-claude-code-쓰기)). 게시자가 **Anthropic** 인지 꼭 확인 |
| Markdown 미리 보기 | 설치 불필요 (기본 내장) | `.md` 문서를 예쁘게 보기: `⌘⇧V` 또는 편집기 **오른쪽 위 미리 보기 버튼** (나란히 보기는 `⌘K` 다음 `V`) |
| Mermaid 미리 보기 (예: *Markdown Preview Mermaid Support*) | 선택 | 문서 안의 다이어그램(mermaid)도 미리 보기에 그려 줌 |

## 2. 터미널 기초 (VS Code 안에서)

### 2.1 터미널이 뭔가요?

- **터미널**: 마우스 대신 **글자로 컴퓨터에 일을 시키는 창**입니다. VS Code 아래쪽에 열립니다.
- **명령어**: 터미널에 입력하는 "일 시키는 문장"입니다. 예: `ls` = "이 폴더에 뭐가 있는지 보여 줘".
- **폴더 경로**: 폴더의 "주소"입니다. 예: `/Users/hong/Documents/t-w` 는 "hong 사용자의 문서 폴더 안의 t-w 폴더"라는 뜻입니다.
- **현재 폴더**: 터미널은 항상 "어느 한 폴더 안에 서 있습니다". VS Code 터미널은 **열어 둔 프로젝트 폴더**에서 시작하므로 따로 이동할 일이 거의 없습니다.

> 이 문서의 대부분은 **버튼으로** 할 수 있습니다. 터미널은 설치, 앱 실행, 검사처럼 버튼이 없는 일에만 씁니다.

### 2.2 알아 두면 좋은 명령어 5개

| 명령어 | 뜻 |
|---|---|
| `pwd` | 지금 내가 있는 폴더 경로 보기 |
| `ls` | 지금 폴더 안의 파일 목록 보기 |
| `cd 폴더이름` | 그 폴더로 들어가기 |
| `cd ..` | 한 단계 위 폴더로 나가기 |
| `clear` | 터미널 화면 깨끗이 지우기 |

**이렇게 보이면 정상**

```
$ pwd
/Users/hong/Documents/t-w
$ ls
README.md   app   checks   docs   main.js   package.json ...
```

### 2.3 터미널 사용 팁

- [ ] 명령어를 붙여 넣은 뒤 **`Enter`를 눌러야** 실행됩니다.
- [ ] 실행 중인 걸 멈추려면 **`Ctrl + C`** (맥도 `Cmd`가 아니라 `Ctrl`).
- [ ] `↑` 키를 누르면 방금 쳤던 명령어가 다시 나옵니다.
- [ ] 비밀번호를 칠 때는 **화면에 아무것도 안 보이는 게 정상**입니다. 그냥 치고 `Enter`.
- [ ] 터미널 오른쪽 위 `+` 로 터미널을 하나 더 열 수 있습니다. (앱을 켜 둔 채 다른 명령을 칠 때 유용)
- [ ] 영어로 된 긴 글이 나와도 당황하지 마세요. **마지막 몇 줄**만 보면 대부분 충분합니다.

## 3. 처음 한 번 설정

### 3.1 필요한 프로그램 설치

| 프로그램 | 왜 필요한가요 | 설치 |
|---|---|---|
| **VS Code** | 모든 작업을 하는 곳 | [1장](#1-vs-code-준비하기) |
| **Git** | 파일 변경 기록 관리, GitHub와 주고받기 | 맥: VS Code 터미널에 `git --version` 입력 → 설치 창이 뜨면 "설치". Windows: git-scm.com 에서 받기 |
| **Node.js** (LTS) | 앱 실행, 검사, Claude Code(터미널판) 설치에 필요 (`npm` 이 같이 깔림) | nodejs.org 에서 **LTS** 버전 받기 |

설치 후 **VS Code를 완전히 껐다가 다시 켜고**, 터미널에서 확인합니다.

```bash
git --version
node --version
npm --version
```

**이렇게 보이면 정상** (숫자는 달라도 됩니다)

```
git version 2.4x.x
v22.x.x
10.x.x
```

> `command not found` 가 나오면 설치가 안 된 것입니다. 설치 후 VS Code를 다시 켜 보세요.

### 3.2 Git에 내 정보 알려 주기 (한 번만, 터미널)

커밋에 "누가 바꿨는지"가 기록됩니다. GitHub 계정과 같은 이메일을 쓰세요.

```bash
git config --global user.name "홍길동"
git config --global user.email "내GitHub이메일@example.com"
git config --global pull.rebase true
```

- 마지막 줄은 "최신 내용을 받을 때 기록을 깔끔하게 한 줄로 이어 붙여라(rebase)"라는 설정입니다.
- 이걸 해 두면 VS Code의 **끌어오기(Pull)** 와 **변경 내용 동기화(Sync)** 버튼도 자동으로 이 방식을 씁니다. 이 프로젝트의 권장 설정입니다.

### 3.3 프로젝트 내려받기 (clone)

- **저장소(repository)**: 프로젝트 파일과 그 **변경 기록 전체**를 담은 상자입니다. 이 프로젝트의 저장소는 GitHub에 있습니다: https://github.com/grk-cmd/t-w
- **clone(클론)**: 저장소를 내 컴퓨터로 통째로 복사해 오는 것입니다.

**방법 A. VS Code 버튼으로**

1. VS Code에서 폴더를 아무것도 열지 않은 상태로, 왼쪽 **소스 제어** 아이콘(`⌃⇧G`)을 누릅니다.
2. **리포지토리 복제(Clone Repository)** 버튼 → 주소 칸에 `https://github.com/grk-cmd/t-w.git` 붙여 넣기 → `Enter`
3. 저장할 위치로 **문서(Documents)** 폴더를 고릅니다.
4. 끝나면 "복제한 리포지토리를 여시겠습니까?" → **열기**

**방법 B. 터미널로**

```bash
cd ~/Documents
git clone https://github.com/grk-cmd/t-w.git
```

끝나면 **파일 → 폴더 열기…** 로 `문서/t-w` 를 엽니다.

**이렇게 보이면 정상** (방법 B)

```
Cloning into 't-w'...
Receiving objects: 100% ...
Resolving deltas: 100% ...
```

### 3.4 앱에 필요한 부품 설치

`t-w` 폴더를 연 VS Code에서 터미널(`` ⌃` ``)을 열고:

```bash
npm install
```

- 앱이 쓰는 부품(라이브러리)을 `node_modules` 폴더에 내려받습니다. 몇 분 걸릴 수 있습니다.
- 노란 `WARN` 은 대부분 괜찮습니다. 빨간 `ERR!` 이 나오면 화면을 캡처해 개발자에게 보내 주세요.

### 3.5 앱 켜 보기, 검사 돌려 보기

| 하고 싶은 것 | 명령어 | 결과 |
|---|---|---|
| 앱 실행 | `npm start` | Together Working 창이 뜹니다. 끄려면 앱을 닫거나 터미널에서 `Ctrl + C` |
| 자동 검사 | `npm run check` | 프로젝트가 멀쩡한지 확인합니다 |

`npm run check` **이렇게 보이면 정상**

```
...
✗ (첫 회차에 실패한 줄이 몇 개 보일 수 있음)
...
✓ ...
빨강 0
```

- **마지막 줄에 `빨강 0`** 이 보이면 통과입니다.
- 중간에 첫 회차 `✗` 표시가 있다가 나중에 통과하는 건 **정상**입니다. 마지막 줄만 보세요.
- 마지막 줄이 `빨강 1` 이상이면, 화면을 캡처해 개발자에게 보내거나 Claude에게 "이 결과 설명해 줘"라고 물어보세요.

### 3.6 설정 체크리스트

- [ ] VS Code가 한국어로 보인다
- [ ] Claude Code 확장(Anthropic)이 설치됐다
- [ ] 터미널에서 `git --version`, `node --version` 이 숫자를 보여 준다
- [ ] `git config --global pull.rebase true` 를 실행했다
- [ ] VS Code로 `t-w` 폴더를 열었고, 왼쪽 아래 상태 표시줄에 `main` 이 보인다
- [ ] `npm install` 이 끝났고 `npm start` 로 앱 창이 떴다
- [ ] `npm run check` 마지막 줄이 `빨강 0` 이다
- [ ] (올리기까지 하려면) 개발자에게 GitHub 저장소 **협업자(collaborator) 권한**을 요청했다

## 4. Claude Code 쓰기

**Claude Code**는 대화하는 AI 도우미입니다. 프로젝트 파일을 읽고, 설명하고, 고치고, 명령어도 대신 실행해 줍니다. 단, **실행 전에 꼭 허락을 구합니다.** 그 허락을 잘 판단하는 게 핵심입니다.

VS Code에서 쓰는 방법은 두 가지입니다. **편한 쪽 하나만 쓰면 됩니다.**

| | 방법 A. 공식 확장 (추천) | 방법 B. VS Code 터미널 |
|---|---|---|
| 준비 | 확장에서 **Claude Code** (게시자 Anthropic) 설치 | 터미널에서 설치 명령 실행 (아래) |
| 여는 법 | 편집기 오른쪽 위 또는 왼쪽 막대의 **Claude 아이콘(반짝이 모양)** | 터미널에 `claude` 입력 |
| 장점 | 채팅창처럼 편함, 바뀐 내용을 나란히 비교해 보여 줌 | 모든 기능, 단축키를 그대로 쓸 수 있음 |

> 공식 확장의 화면과 버튼 위치는 **버전에 따라 조금 다를 수 있어요.**

### 4.1 방법 A. 공식 확장

1. 확장(`⌘⇧X`)에서 `Claude Code` 검색 → 게시자가 **Anthropic** 인 것 → **설치**
2. 편집기 오른쪽 위(또는 왼쪽 작업 막대)의 **Claude 아이콘** 을 누르면 대화 패널이 열립니다.
3. 처음에는 로그인 안내가 나옵니다. 브라우저가 열리면 로그인하고 VS Code로 돌아옵니다.
4. 아래 입력칸에 한국어로 질문하면 됩니다.

### 4.2 방법 B. VS Code 터미널에서

```bash
npm install -g @anthropic-ai/claude-code
```

- 이 방법이 안 되면 **공식 문서의 설치 안내를 따르세요.** (공식 설치 프로그램도 있습니다.)
- 설치 확인: `claude --version`

프로젝트를 연 VS Code의 터미널에서:

```bash
claude
```

- 처음이면 로그인 안내가 나옵니다. 안 나오면 Claude 안에서 `/login` 을 입력하세요.

### 4.3 한국어로 물어보기

그냥 평소 말투로 쓰면 됩니다.

| 하고 싶은 것 | 이렇게 물어보세요 |
|---|---|
| 프로젝트 파악 | "이 프로젝트가 뭐 하는 앱인지 비개발자에게 설명하듯 알려 줘" |
| 위치 찾기 | "로그인 화면 문구는 어느 파일에 있어?" |
| 수정 전 계획 | "README의 설치 안내를 고치고 싶어. 바꾸기 전에 먼저 계획만 보여 줘" |
| 결과 해석 | "방금 `npm run check` 결과에서 빨강이 뭔지 설명해 줘" |
| 위험 확인 | "이 명령 실행하면 뭐가 바뀌어? 되돌릴 수 있어?" |
| 변경 확인 | "지금까지 바꾼 내용을 쉽게 요약해 줘" |
| 충돌 설명 | "소스 제어에 충돌 표시가 떴어. 무슨 상황인지 설명만 해 줘. 아무것도 고치지 마" |

### 4.4 허락(권한) 요청 화면 읽는 법

Claude가 파일을 고치거나 명령어를 실행하려 하면 허락을 묻는 화면이 뜹니다. (확장에서는 버튼, 터미널에서는 번호 목록)

```
Claude wants to run: git push
  1. Yes
  2. Yes, and don't ask again for ...
  3. No, and tell Claude what to do differently
```

| 상황 | 이렇게 하세요 |
|---|---|
| 무슨 일인지 **이해했고** 안전하다 | `Yes` |
| 무슨 일인지 **모르겠다** | `No` 를 고르고 "이게 뭐 하는 명령인지 먼저 설명해 줘"라고 입력 |
| "다시 묻지 않기(don't ask again)" | 비개발자는 **쓰지 않는 걸 추천**. 매번 확인하는 게 안전합니다 |

### 4.5 자주 쓰는 키와 명령

| 입력 | 하는 일 |
|---|---|
| `Esc` | Claude가 하던 일을 **즉시 멈춤**. 이상하다 싶으면 바로 누르세요 |
| `/clear` | 대화를 지우고 새로 시작 (주제가 바뀔 때) |
| `/login` | 로그인 / 계정 바꾸기 |
| `!` + 명령어 | (터미널 방식) Claude를 거치지 않고 **내가 직접** 명령 실행. 예: `!git status` |
| `/tui default` | (터미널 방식) 화면 스크롤이 안 될 때. 전체 화면 모드를 일반 모드로 바꿈 |
| `Ctrl + C` 두 번 | (터미널 방식) Claude 종료 |

### 4.6 Claude와 일할 때 지킬 것

- [ ] **바꾸기 전에 설명부터** 해 달라고 하세요. ("먼저 계획만 보여 줘")
- [ ] 한 번에 한 가지 일만 시키세요. 작게 나눌수록 실수가 줄어듭니다.
- [ ] 커밋 전에는 **소스 제어에서 바뀐 내용(diff)을 꼭 직접 확인**하세요. ([5.3](#53-작은-수정-올리기-버튼-순서))
- [ ] **비밀번호, API 키, 토큰, 개인정보는 절대 대화창에 붙여 넣지 마세요.**
- [ ] Claude에게 커밋을 맡길 때는 "**Co-Authored-By 같은 Claude 서명 줄은 넣지 마**"라고 말해 주세요. (이 프로젝트 규칙)
- [ ] Claude가 확신 있게 말해도 틀릴 수 있습니다. 중요한 건 개발자에게 한 번 더 확인하세요.

## 5. git 기본 흐름 (VS Code 버튼으로)

### 5.1 먼저 단어부터

| 용어 | 한 줄 설명 | 비유 |
|---|---|---|
| **커밋 (commit)** | 바꾼 내용을 설명과 함께 **기록으로 저장**하는 것 | 게임의 "세이브" |
| **푸시 (push)** | 내 컴퓨터의 커밋을 **GitHub로 올리는** 것 | 세이브 파일을 클라우드에 업로드 |
| **풀 (pull, 끌어오기)** | GitHub의 최신 커밋을 **내 컴퓨터로 받는** 것 | 클라우드에서 최신 세이브 다운로드 |
| **브랜치 (branch)** | 기록의 **갈래**. 기본 갈래 이름은 `main` | 같은 문서의 "작업용 사본" |
| **충돌 (conflict)** | 나와 다른 사람이 **같은 줄을 다르게** 고쳐서 git이 어느 쪽을 쓸지 모르는 상태 | 공동 문서에서 같은 문장을 동시에 고침 |

### 5.2 소스 제어 화면 둘러보기

왼쪽 작업 막대의 **가지 모양 아이콘** = **소스 제어**. 단축키 `⌃⇧G` (Windows `Ctrl+Shift+G`)

| 화면 요소 | 뜻 |
|---|---|
| 아이콘 위 숫자 배지 | 바뀐 파일 개수 |
| **변경 사항(Changes)** 목록 | 고쳤지만 아직 커밋에 담지 않은 파일 |
| **스테이징된 변경 사항(Staged Changes)** 목록 | 이번 커밋에 담기로 고른 파일 |
| 파일 옆 글자 `M` / `U` / `D` | 수정됨(Modified) / 새 파일(Untracked) / 삭제됨(Deleted) |
| 파일 이름 클릭 | 왼쪽(전)·오른쪽(후) **나란히 비교 화면(diff)** 이 열림. 빨강 = 지운 내용, 초록 = 새 내용 |
| 파일 옆 `+` 버튼 | 그 파일을 **스테이징**(이번 커밋에 담기) |
| 파일 옆 `↶` 버튼 | 그 파일의 수정을 **되돌리기** (취소 불가, 조심!) |
| 맨 위 메시지 입력칸 | 커밋 메시지 쓰는 곳 |
| **✓ 커밋(Commit)** 버튼 | 커밋하기 |
| `…` (더 보기) 메뉴 | 끌어오기(Pull), 푸시(Push) 등 |

### 5.3 작은 수정 올리기 (버튼 순서)

| 단계 | VS Code에서 | 의미 |
|---|---|---|
| ① 최신 받기 | 소스 제어 → `…` → **끌어오기(Pull)** | 다른 사람이 바꾼 걸 먼저 받습니다 |
| ② 부품·검사 | 터미널에서 `npm install` → `npm run check` | 시작 전 상태가 `빨강 0` 인지 |
| ③ 수정 | 탐색기에서 파일을 열어 고치고 **저장(`⌘S`)** | 저장 안 하면 git에 안 보입니다 |
| ④ 확인 | 소스 제어에서 **바뀐 파일 목록** 확인 | **내가 안 건드린 파일이 있으면 멈추고 문의** |
| ⑤ 내용 확인 | 파일 이름 클릭 → 비교 화면에서 빨강/초록 확인 | 의도한 내용만 바뀌었는지 |
| ⑥ 담기 | 올릴 파일 옆 **`+`** | 이번 커밋에 넣을 파일만 고르기 |
| ⑦ 메시지 | 맨 위 칸에 `docs: 설치 안내 문구 수정` | [5.4](#54-커밋-메시지-쓰는-법) 규칙대로 |
| ⑧ 커밋 | **✓ 커밋** 버튼 | 세이브 |
| ⑨ 올리기 | **변경 내용 동기화(Sync Changes)** 버튼 (또는 `…` → 푸시) | GitHub에 업로드 |

> **"변경 내용 동기화"는 무엇을 하나요?** 끌어오기(pull) 다음에 푸시(push)를 **한 번에** 해 줍니다.
> 3.2에서 `pull.rebase true` 를 설정했다면 끌어오기는 rebase 방식으로 동작합니다.
> **충돌이 났거나 이상한 알림이 떠 있을 때는 누르지 마세요.** ([5.6](#56-충돌conflict이-났어요))

> **"스테이징된 변경 사항이 없습니다. 모든 변경 사항을 커밋할까요?"** 라는 창이 뜨면 **아니요** 를 누르고 ⑥으로 돌아가세요.
> 모두 커밋하면 원치 않는 파일까지 올라갈 수 있습니다.

**잘 됐는지 확인**: 소스 제어 목록이 비어 있고, 아래 상태 표시줄의 동기화 표시에 숫자(↑1 등)가 없으면 올리기까지 끝난 것입니다.

**참고: 같은 일을 터미널로 하면**

| 버튼 | 터미널 명령 |
|---|---|
| 끌어오기(Pull) | `git pull --rebase` |
| 바뀐 파일 목록 보기 | `git status` |
| 비교 화면 | `git diff` (빠져나올 때 `q`) |
| `+` 스테이징 | `git add docs/파일이름.md` |
| ✓ 커밋 | `git commit -m "docs: …"` |
| 푸시 | `git push` |

### 5.4 커밋 메시지 쓰는 법

형식: **`타입(스코프): 무엇을 했는지`** — 한국어로, 마침표 없이, 72자 이내.

| 좋은 예 | 나쁜 예 |
|---|---|
| `docs: 비개발자 가이드 추가` | `수정` |
| `docs(handoff): 10월 회의 결과 정리` | `여러 가지 고침` |
| `fix(mac): 창 제목 오류 수정` | `docs/fix: 문서랑 버그` (두 가지를 섞음) |

- 비개발자가 주로 쓰는 타입은 **`docs`** (문서) 입니다. 다른 타입은 [GIT_CONVENTION.md](GIT_CONVENTION.md)를 보세요.
- **한 커밋에는 한 가지 의도만.** 문서 수정과 문구 수정이 따로라면 커밋도 둘로 나눕니다.
- **절대 커밋하면 안 되는 파일**: `oauth-config.js`, `.env`, `.idea` 폴더. 비밀값이나 개인 설정이 들어 있습니다.
  → 그래서 "모두 스테이징"보다 **파일마다 `+`** 로 하나씩 담는 걸 권합니다.

### 5.5 푸시가 거절됐어요 (rejected)

"원격에 내가 없는 커밋이 있습니다" / `rejected` / `fetch first` 같은 알림이 뜨면:

- 뜻: "내가 작업하는 사이에 다른 사람이 먼저 올렸어요." 고장이 아닙니다.
- 해결: `…` → **끌어오기(Pull)** → 문제없이 끝나면 다시 **푸시**. (터미널: `git pull --rebase` → `git push`)
- "강제 푸시(Force Push)" 메뉴는 **절대 누르지 마세요.**

### 5.6 충돌(conflict)이 났어요

VS Code에서는 이렇게 보입니다.

- 소스 제어에 **병합 변경 사항(Merge Changes)** 목록이 생기고 파일 옆에 `!` 표시
- 파일을 열면 색칠된 두 덩어리와 그 위에 버튼들:
  **현재 변경 사항 수락 | 수신 변경 사항 수락 | 두 변경 사항 모두 수락 | 변경 사항 비교**
  (영어: Accept Current Change / Accept Incoming Change / Accept Both Changes / Compare Changes)

| 하세요 | 하지 마세요 |
|---|---|
| **멈추고** 화면을 캡처해 개발자에게 보내기 | 아무 수락 버튼이나 눌러 보기 |
| Claude에게 "충돌 났어. 무슨 상황인지 **설명만** 해 줘"라고 묻기 | **변경 내용 동기화** 버튼 누르기 |
| 잘 모르겠으면 터미널에서 `git rebase --abort` 로 **끌어오기 전 상태로 되돌리기** (내 커밋은 남아 있음) | 강제 푸시, `git reset --hard` |
| | 충돌 표시(`<<<<<<<`, `=======`, `>>>>>>>`)가 남은 파일을 그대로 커밋 |

### 5.7 버전 올리기 (참고)

앱 버전 올림은 보통 개발자가 하지만, 맡게 되면 터미널에서 이 순서만 씁니다. `main` 에서 바로 합니다.

```bash
npm version patch -m "chore: %s"
git push --follow-tags
```

- 버전 올림 ≠ 배포입니다. 앱 배포는 그다음에 `npm run release` 로 합니다.

## 6. 자주 겪는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 소스 제어에 "**열린 폴더에 git 리포지토리가 없습니다**" | **엉뚱한 폴더**를 열었음 (상위 폴더나 `docs` 등) | 파일 → 폴더 열기 → **`t-w` 폴더 자체**를 열기 |
| 소스 제어에 "**Git을 설치하세요**" / git을 찾을 수 없음 | Git 미설치 | [3.1](#31-필요한-프로그램-설치)대로 설치 → **VS Code 완전히 재시작** |
| `` ⌃` `` 를 눌러도 터미널이 안 열림 | 한글 입력 상태라 백틱이 다른 글자로 입력됨 | 영문 입력으로 바꾸고 다시, 또는 메뉴 **보기 → 터미널** |
| 터미널이 열렸는데 입력이 안 됨 | 포커스가 편집기에 있음 | 터미널 영역을 한 번 클릭 |
| `command not found: npm` / `node` | Node.js 미설치 | nodejs.org 에서 LTS 설치 → VS Code 재시작 |
| `command not found: claude` | Claude Code(터미널판) 미설치 | `npm install -g @anthropic-ai/claude-code` 또는 공식 문서 설치 안내. 아니면 **공식 확장** 사용 |
| `npm install -g` 중 `EACCES` / permission denied | 전역 설치 권한 문제 | `sudo` 쓰지 말고 개발자에게 문의, 또는 공식 설치 프로그램 / 공식 확장 사용 |
| Claude 아이콘이 안 보임 | 확장 미설치 또는 비활성 | 확장에서 Claude Code(Anthropic) 설치·사용 설정 → VS Code 재시작 |
| 푸시할 때 `Permission ... denied` / `403` | 저장소에 **올릴 권한이 없음** | 개발자에게 **협업자(collaborator) 초대** 요청 → GitHub 메일에서 수락 |
| 푸시할 때 GitHub 로그인 창이 뜸 | GitHub 로그인 필요 | 안내대로 **브라우저로 GitHub 로그인** 허용. 비밀번호를 대화창이나 문서에 적지 마세요 |
| 푸시 거절(`rejected`, `fetch first`) | 다른 사람이 먼저 올림 | 끌어오기 → 푸시 ([5.5](#55-푸시가-거절됐어요-rejected)) |
| 병합 변경 사항 / `CONFLICT` | 같은 줄을 둘이 고침 | 멈추고 문의 ([5.6](#56-충돌conflict이-났어요)) |
| 고친 파일이 소스 제어에 안 보임 | 저장 안 함 | 탭 이름 옆 `●` 가 있으면 `⌘S` 로 저장 |
| `.idea`, `oauth-config.js` 등이 목록에 보임 | 개인·비밀 파일 | **스테이징하지 마세요.** 개발자에게 알리기 |
| Claude(터미널판) 화면 스크롤이 안 됨 | 전체 화면 렌더러 사용 중 | Claude 안에서 `/tui default` |
| `DeprecationWarning: url.parse() ...` | 부품 쪽의 옛 방식 경고 | **무시해도 됩니다.** 동작에 영향 없음 |
| `npm WARN ...` (노란색) | 경고 | 대부분 무시해도 됩니다. `ERR!` (빨간색)만 문의 |
| `npm run check` 중간에 `✗` | 첫 회차 실패 후 재시도 | **마지막 줄 `빨강 0`** 이면 정상 |
| 터미널 명령이 끝나지 않고 멈춰 있음 | 실행 중이거나 입력 대기 | 기다리거나 `Ctrl + C` (`git diff` 화면이면 `q`) |

### 개발자에게 물어볼 때 보내면 좋은 것

- [ ] 내가 **누른 버튼이나 입력한 명령어**
- [ ] 화면 캡처 (알림 문구, 터미널 마지막 20줄 정도)
- [ ] 소스 제어 화면 캡처 (또는 터미널 `git status` 결과)
- [ ] 비밀번호·토큰이 보이면 **가리고** 보내기

| **명령 팔레트** | `⌘⇧P` 로 여는 검색창. 기능 이름을 치면 실행됨 |
| **탐색기** | VS Code 왼쪽의 폴더·파일 목록 |
| **소스 제어** | VS Code의 git 화면 (가지 모양 아이콘, `⌃⇧G`) |
| **터미널** | 글자로 컴퓨터에 일을 시키는 창. VS Code 아래쪽에 열림 |
| **명령어** | 터미널에 입력하는 "일 시키는 문장" |
| **폴더 경로** | 폴더의 주소. 예: `/Users/hong/Documents/t-w` |
| **`~` (물결)** | 내 사용자 폴더(홈 폴더)를 줄여 쓴 것 |
| **저장소 (repository, 리포지토리)** | 프로젝트 파일 + 변경 기록 전체를 담은 상자 |
| **GitHub** | 저장소를 인터넷에 올려 두고 함께 쓰는 서비스 |
| **clone (클론, 복제)** | GitHub 저장소를 내 컴퓨터로 통째로 복사 |
| **스테이징 (`+`, `git add`)** | 이번 커밋에 넣을 파일을 골라 담기 |
| **커밋 (commit)** | 변경 내용을 설명과 함께 기록으로 저장 |
| **푸시 (push)** | 내 커밋을 GitHub로 올리기 |
| **풀 (pull, 끌어오기)** | GitHub의 최신 커밋을 내 컴퓨터로 받기 |
| **변경 내용 동기화 (Sync)** | 끌어오기 + 푸시를 한 번에 |
| **rebase (리베이스)** | 내 커밋을 최신 기록 **뒤에** 다시 이어 붙이기. `pull.rebase true` 설정과 관련 |
| **브랜치 (branch)** | 기록의 갈래. 기본은 `main` |
| **main** | 이 프로젝트의 기본(공식) 브랜치 |
| **충돌 (conflict)** | 같은 줄을 서로 다르게 고쳐서 git이 결정을 못 하는 상태 |
| **diff (디프, 비교)** | 바뀌기 전과 후의 차이. 빨강 = 삭제, 초록 = 추가 |
| **npm** | Node.js의 부품 관리 도구. `npm install`, `npm start` 등에 씀 |
| **node_modules** | `npm install` 로 받은 부품이 모이는 폴더 (커밋하지 않음) |
| **Electron** | 웹 기술로 데스크톱 앱을 만드는 도구. Together Working이 이걸로 만들어졌음 |
| **Firebase** | Google의 서버 서비스. 이 앱의 데이터베이스(Realtime Database), 로그인(Auth), 파일 저장(Storage), 서버 함수(Functions), 웹 호스팅(Hosting)을 담당 |
| **운영 환경 (production)** | 실제 사용자들이 쓰는 진짜 서비스. 실수하면 바로 영향이 감 |
| **배포 (release / deploy)** | 만든 것을 사용자에게 내보내는 것 |
| **Claude Code** | 파일을 읽고 고치는 AI 도우미. VS Code 공식 확장 또는 터미널에서 사용 |
| **권한 요청 (permission prompt)** | Claude가 무언가 실행하기 전에 내 허락을 묻는 화면 |
| **협업자 (collaborator)** | GitHub 저장소에 직접 올릴 수 있는 권한을 받은 사람 |
