# 작업 현황 — 누가 무엇을 만지는 중인가

여럿이 같은 일 · 같은 파일을 동시에 고치지 않게 하려고 둔다. **누구든(사람 · 세션 · 웹 세션) 작업을 시작하기 전에 현황부터 본다.**

현황은 이 파일이 아니라 **GitHub** 에 있다. 파일 표로 두면 착수 · 작업중 · PR 번호 · 작업완료마다 main 에 커밋이 쌓여서 옮겼다.

| 상태 | 어디에 | 누가 쓰나 |
|---|---|---|
| **검토중** — 보기만 · 아직 안 고침 | 이슈 + 라벨 `status:검토중` | 보기 시작한 사람 · 세션 |
| **작업중** | 열린 PR(초안 아님) — 본문 «담당» 줄 · «건드리는 파일» 칸 | 착수한 사람 · 세션 |
| **작업완료** | 머지된 PR | 아무도 안 씀(머지가 기록) |

## 보기
```bash
python3 .claude/hooks/role-start.py --board
```
판마다 열린 PR(파일 수 · 담당) · 판 밖 PR(main · hotfix · harness) · 검토중 이슈 · **열린 PR 끼리 겹치는 파일**(본문 «건드리는 파일» + 실제 diff) · 판끼리 겹치는 파일을 한 장으로 찍는다.
새 세션을 main · 판 브랜치 위에서 열면 시작 hook 이 같은 요약을 붙인다. gh 가 없거나 못 닿으면 «못 읽음» 으로 적는다(«없음» 과 다르다).

## 작업 시작 절차
1. **현황을 본다** — 위 명령.
2. **같은 일 · 같은 파일이 있으면 상태대로**:
   - **검토중** 이슈 → 시작하지 말고 사용자에게 «제가 할까요, ○○(그 이슈 담당)이 할까요?» 를 묻는다.
   - **작업중** PR 과 파일이 겹침 → 시작하지 말고 그 PR 담당과 먼저 맞춘다(PR 코멘트).
3. **없으면 PR 을 먼저 연다** — 판 브랜치에서 작업 브랜치를 따고 빈 커밋 하나로 push 한 뒤 PR 을 연다. 본문은 `.github/pull_request_template.md` 틀 — **«담당»** 줄과 **«건드리는 파일»** 칸을 채운다(코드가 오르기 전에는 이 칸으로만 겹침을 본다).
   ```bash
   git commit --allow-empty -m "chore: <무엇을> 착수"
   git push -u origin <브랜치>
   gh api repos/grk-cmd/t-w/pulls -f title='<커밋 제목 형식>' -f head='<브랜치>' -f base='release/X.Y.Z' -F body=@본문.md
   ```
   - 초안(draft)으로 열지 않는다 — 웹 세션은 초안을 풀 수 없다(GraphQL 이 막혀 있음). 머지는 컨펌 · 검증 상태값이 있어야 되니 미리 열어도 잘못 머지되지 않는다.
   - 보기만 할 일(원인 조사 · 점검)은 PR 대신 이슈를 열고 라벨 `status:검토중` 을 붙인다(`gh api repos/grk-cmd/t-w/issues -f title='<무엇을 보나>' -f body='담당: <이름>' -f 'labels[]=status:검토중'`)(본문 첫 줄 «담당: 이름»). 고치기 시작하면 PR 을 열고 본문에 이슈 번호를 적는다(`#12`). 머지되면 이슈를 닫는다.
4. 머지는 `/ship`. 끝나면 아무것도 적지 않는다.

- 웹 관리자 📋 할 일(`adminTodos`)에는 버그 제보와 관련된 일만 적는다. 기능 · 계획 · «지금 누가 무엇을 하나» 는 PR · 이슈가 정본이다.

## 규칙
- **판은 사용자가 고른다** — 작업 전에 «어느 버전에 릴리스될 작업인가» 를 묻고 그 판 `release/X.Y.Z` 에서 딴다. 긴급 수정만 `hotfix/*`, 하네스만 `harness/*` 를 main 에서.
- **main · release/* 에는 직접 push 하지 않는다**(예외 없음 — 가드가 막는다).
- **머지는 `/ship`** — 컨펌자 · 검증자 통과 → CI → 머지. 승인은 가드 자리를 바꾸는 PR 만(`risk.py --owner <PR>`). 로컬에서 검사 전체를 다시 돌리지 않는다(고친 검사만 · 전체는 CI).
- `checks/CHECKS.md` 에 개정 번호 · 기록은 적지 않는다(내력은 git). §3 해시만 맞춘다.
- **클릭 통과(setIgnoreMouseEvents)를 정하는 조건은 `app/parts/launcher/click-through-policy.js` 한 곳에만 쓴다.** 다른 파일에 쓰면 `sim-click-through-policy.js` 가 빨강이다.
- **담당 이름은 남과 겹치지 않게** 쓴다(예: «검증-도우미1» · «계정 세션» · 사람 이름). 모든 세션이 같은 GitHub 계정이라 PR 작성자로는 누가 누군지 못 가린다.
- 버그 제보를 고친 PR 은 제목 끝에 `(B-MMDD-n)` 을 붙인다 — 제보 → 수정 짝은 PR 제목으로 찾는다.
