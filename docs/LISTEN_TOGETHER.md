# 같이 듣기 — 설계 (0.13.0)

방을 만들 때 «같이 듣기» 를 켜면, **현재 방장이 DJ** 가 되어 자기 플레이리스트를 방 사람들과 같은 곡 · 같은 위치로 함께 듣는다.
방 목록 로비(`docs/ROOM_LOBBY.md`)의 8장 «나눠 올릴 PR» 5번이다. 화면 시안은 사용자 확인을 받았다(같이 듣기 시안 아티팩트).

## 1. 정해진 것 (사용자 확인)

| 무엇 | 정한 것 |
|---|---|
| 누가 트나 | 현재 방장 = 현재 DJ. 로비 카드 · 방 안 표시도 «현재 DJ» |
| 어느 방 | 워킹룸 · 투게더룸 둘 다 · 시크릿룸도(아래) |
| 언제 켜나 | 방을 만들 때만(만든 뒤엔 못 바꿈 — 로비 설계 5.1 과 같다) |
| 시크릿룸 | F1 설정 «방 만들기 / 참여하기» 의 시크릿룸 줄 아래 «🎧 내 시크릿룸을 같이 듣기로 열기». 주인이 방을 **열 때** 적용(이미 열린 방은 다음에 열 때부터). 설정은 **이 기기에 기억**(한 계정 한 기기라 따라다니는 것과 같음) |
| 듣는 사람이 할 수 있는 것 | 내 소리 크기 · 음소거만. «내 플레이리스트에 담기» 는 이번엔 안 함 |
| 플레이리스트 버튼 | 같이 듣기 방에서는 상태칩 🎵 버튼이 🎧 «같이 듣기» 가 되어 같이 듣기 창을 연다. 방을 나가면 원래대로 |
| 방에 들어올 때 | 내 플레이리스트가 멈추고 지금 곡을 지금 위치부터 |
| 방을 나갈 때 | 같이 듣기가 멈추고 **내 플레이리스트는 멈춘 채로**(다시 틀려면 🎵 에서) |
| DJ 가 나갈 때 | 승계 규칙대로 다음 방장이 DJ. **지금 곡은 끝까지** 틀고, 그다음부터 새 DJ 의 플레이리스트 |
| 로비 카드 | 지금 곡 제목은 안 보임(«같이 듣기» 딱지 · «현재 DJ» 만 — #483 그대로) |
| DJ 표시 | DJ 머리 위 이름표에 «🎧 DJ» |

## 2. 데이터

### 2.1 `rooms/{방}/_meta.music` (이미 있음 — #479)
- 불. 방을 만들 때만 쓴다(방 만들기 창 · 시크릿룸은 주인이 빈 방을 열 때 이 기기 설정으로). 로비 사본은 `mu` 로 옮긴다(이미 됨).

### 2.2 `rooms/{방}/_music` (새 칸)
```
rooms/{방}/_music = {
  id:     'jfKfPfyJRdk',      // 유튜브 videoId (11자 · 영숫자 _ -)
  title:  'lofi hip hop radio', // 1~100자 — 화면에는 글로만(TwSafeHtml · textContent)
  by:     '<DJ 의 내 코드>',    // 쓴 사람 — 승계 뒤 «지금 곡은 옛 DJ 것» 을 가린다
  at:     1729500000000,       // 이 곡 0초 지점의 서버 시각(ms) — 재생 중일 때의 위치 = (서버 지금 − at) / 1000
  paused: false,
  pos:    0,                   // 멈췄을 때의 위치(초) — paused 일 때만 뜻이 있다
  seq:    7                    // 곡 · 멈춤이 바뀔 때마다 +1 — 늦게 온 쓰기 · 같은 곡 다시 틀기를 가린다
}
```
- **쓰는 때**: DJ 가 곡을 바꾸거나(다음 · 이전 · 곡 끝) 멈추거나 다시 틀 때만 `set` 한 번(수십 바이트). 재생 중 매초 쓰지 않는다.
- **읽는 때**: 같이 듣기 방(`_meta.music === true`) 안에 있는 동안만 이 칸 하나를 `onValue` 구독. 방을 나가면 끊는다. 일반 방은 구독하지 않는다.
- **위치 계산**: 서버 시각은 이미 있는 `_svNow`(firebase-init — `.info/serverTimeOffset` 보정). 각자 계산하므로 곡 진행 중에 오가는 데이터가 없다.
- **방이 지워질 때**: `rooms/{방}` 이 통째로 지워지면 같이 사라진다(따로 정리 없음).

### 2.3 시크릿룸 설정 — 이 기기 `localStorage` `tw.secretRoomMusic`
- `'1'` 이면 주인이 빈 시크릿룸을 열 때 `_meta.music = true` 로 연다. 서버 · 규칙 칸을 늘리지 않는다.

## 3. 규칙 (`firebase/firebase-database-rules.json`)
- `rooms/$room/_music`: `.write: true` + 모양 검사(`_meta` 와 같은 수준 — 방장인지 서버가 확인하지 못한다. 화면에서 DJ 만 쓰게 막고, «DJ 만» 은 방 서버가 지킨다).
  - `id` 문자열 `^[A-Za-z0-9_-]{11}$` · `title` 문자열 1~100 · `by` 문자열 1~64 · `at` 숫자 · `paused` 불 · `pos` 숫자 0 이상 · `seq` 정수 0 이상 · 그 밖의 칸 거절.
  - 지우기(null) 허용 — DJ 플레이리스트가 비었을 때 «틀 곡 없음».
- `.read`: 방 멤버 읽기와 같은 조건(`rooms/$room` 의 읽기를 그대로 받는다).
- 에뮬레이터 검사(`firebase/scripts/rules-emu-check.js`)에 모양 · 거절 경우를 더한다.

## 4. 앱

| 파일 | 할 일 |
|---|---|
| `room/listen-model.js` (새 · 순수) | 지금 위치 계산(`posOf(music, now)`) · 어긋남 판정(5초 넘으면 맞춤 — 그보다 작으면 그대로) · 다음 곡 고르기(DJ 플레이리스트 순서 · 끝이면 처음) · `_music` 한 줄 만들기(곡 · 멈춤 · 다시 틀기). DOM · firebase 없음 — `sim-listen-model.js` |
| `room/listen-provider.js` (새) | `_music` 구독 · 쓰기 한 곳(지금은 Firebase 옛 길 · 방 서버 meta 가 생기면 여기만 바꾼다) |
| `room/listen-ui.js` (새 · `TwListenUi`) | 같이 듣기 창(DJ 보기 · 듣는 사람 보기 — 시안 1장) · 재생 창 다루기(곡 열기 · 위치 맞추기 · 멈춤 · 소리) · 들어올 때 내 플레이리스트 멈추기 · 승계 뒤 «지금 곡 끝까지» · DJ 이름표 딱지 |
| `status/playlist.js` | 같이 듣기 방이면 🎵 버튼을 🎧 로 바꿔 같이 듣기 창을 연다 · 내 재생을 멈추는 길(`_plStop`)을 deps 로 내놓는다 · 다음 곡 목록(DJ 의 지금 프리셋)을 읽는 함수를 내놓는다 |
| `room/room-create-ui.js` | «🎧 같이 듣기 방» 칸 → `onCreate(채널, { …, music })` |
| `room/room-entry.js` | 만들기 · 빈 방 열기 · 시크릿룸 열기에 `music` 을 `_meta` 로 · 들어감 · 나감 · meta 때 같이 듣기 모듈에 알린다(방 설정 줄과 같은 자리) |
| F1 설정(html · `room-entry.js` 의 F1 시크릿룸 칸) | «🎧 내 시크릿룸을 같이 듣기로 열기» — 시크릿룸 줄과 같은 조건(주인에게만)으로 보인다 |
| `room/overhead.js` | DJ 이름표에 «🎧 DJ» 딱지(현재 방장 · 같이 듣기 방일 때) |
| `firebase-init.js` | `_music` 구독 · 쓰기 두 함수(줄 상한 — 다른 데서 줄여 자리를 만든다) |
| `apps/desktop/main.js` · `preload.js` | 재생 창에 **위치 옮기기**(`companion:bgmSeek(초)` — 주입 스크립트로 `video.currentTime`) · **시작 위치로 열기**(`openPlaylistTrack(url, title, { start })` → 유튜브 주소 `&t=초s`) · 같이 듣기도 지금 플레이리스트 모드의 «곡 끝 · 하트비트(`TWPL:hb:위치`)» 신호를 그대로 받는다 — 새 바깥 주소 없음 |

- **어긋남 맞추기**: 재생 창이 5초마다 보내는 하트비트의 위치와 `posOf(_music)` 을 견준다. 5초 넘게 다르면 `bgmSeek`. 광고 중(하트비트가 멈춤)에는 맞추지 않는다.
- **곡 끝**: 모두의 재생 창이 «곡 끝» 을 보내지만, 다음 곡을 쓰는 건 **지금 DJ 한 사람**(현재 방장)만. 듣는 사람은 다음 `_music` 을 기다린다.
- **승계**: 새 방장 앱은 `_music.by` 가 내가 아니면 «지금 곡은 끝까지» — 그 곡의 «곡 끝» 에서 내 플레이리스트 첫 곡을 쓴다. 내 플레이리스트가 비었으면 `_music` 을 지운다(«틀 곡 없음» 화면).
- **소리**: 듣는 사람의 소리 크기 · 음소거는 이 기기에만(지금 BGM 소리 크기 저장과 같은 자리).
- **오류 번호**: `E-ROOM-05` 같이 듣기 곡을 못 바꿈(쓰기 실패 — DJ 에게만) · `E-ROOM-06` 곡을 못 틂(재생 창 · 유튜브 재생 불가 — 다음 곡으로 넘기는 건 DJ).

## 5. 서버 작업 필요 (`t-w-server` — 이 저장소 밖)
- 방 `meta` 에 `music` 을 받기(방 만들기 `join` 의 `create`) · 방 메시지 `music`(위 2.2 모양)을 **현재 방장만** 보낼 수 있게 · 들어오는 사람에게 지금 `music` 을 같이 준다.
- 서버 시각: 방 서버 방은 서버가 주는 시각으로 `at` 을 맞춘다(Firebase 의 `_svNow` 대신).
- 서버가 생기기 전 앱의 옛 길: Firebase `rooms/{방}/_music` · 방 서버 방에서는 같이 듣기 칸을 숨긴다(방 설정 줄과 같다). 서버가 생기면 바꿀 자리: `room/listen-provider.js`.

## 6. 옛 앱과 섞일 때
- 옛 앱(0.12 이하)은 `_music` 을 모른다 — 같이 듣기 방에 들어와도 음악이 안 나오고 자기 플레이리스트가 그대로 돈다. 사용자 대부분이 0.13.0 으로 올라온 뒤 `config/minRoomVer` 를 올린다(로비 설계 6장과 같은 때).

## 9. 남은 위험
- 유튜브 광고 · 지역 제한 · 퍼가기 금지 곡은 사람마다 다르게 걸린다 — 그 사람만 소리가 안 나고(오류 번호), 방 전체는 그대로 간다.
- 위치는 ±5초 안에서 맞춘다 — 같은 순간에 같은 박자까지는 보장하지 않는다(말로 안내).
