# 같이 듣기 — 설계 (0.13.0)

방을 만들 때 «같이 듣기» 를 켜면, **현재 방장이 DJ** 가 되어 자기 플레이리스트를 방 사람들과 같은 곡 · 같은 위치로 함께 듣는다.
방 목록 로비(`docs/ROOM_LOBBY.md`)의 8장 «나눠 올릴 PR» 5번이다. 화면 시안은 사용자 확인을 받았다(같이 듣기 시안 아티팩트).

## 1. 정해진 것 (사용자 확인)

| 무엇 | 정한 것 |
|---|---|
| 누가 트나 | 현재 방장 = 현재 DJ. 로비 카드 · 방 안 표시도 «현재 DJ» |
| 어느 방 | 워킹룸 · 투게더룸 둘 다 · 시크릿룸도(아래) |
| 언제 켜나 | 방을 만들 때만(만든 뒤엔 못 바꿈 — 로비 설계 5.1 과 같다). 빈 방 선점 · 랜덤 입장으로 연 방은 늘 일반 방 |
| 시크릿룸 | F1 설정 «방 만들기 / 참여하기» 의 시크릿룸 줄 아래 «🎧 내 시크릿룸을 같이 듣기로 열기». 주인이 방을 **열 때** 적용(이미 열린 방은 다음에 열 때부터). 설정은 **이 기기에 기억**(한 계정 한 기기라 따라다니는 것과 같음) |
| 시크릿룸에 주인이 없을 때 | 지금 곡을 끝까지 틀고 **멈춤**(«DJ(방 주인)가 없어서 쉬는 중이에요»). 주인이 들어오면 주인 플레이리스트로 다시 시작. 시크릿룸은 주인만 튼다 |
| 듣는 사람이 할 수 있는 것 | 내 소리 크기 · 음소거만. «내 플레이리스트에 담기» 는 이번엔 안 함 |
| 플레이리스트 버튼 | 같이 듣기 방에서는 상태칩 🎵 버튼이 🎧 «같이 듣기» 가 되어 같이 듣기 창을 연다. 방을 나가면 원래대로 |
| 방에 들어올 때 | 내 플레이리스트가 멈추고 지금 곡을 지금 위치부터 |
| 방을 나갈 때 | 같이 듣기가 멈추고 **내 플레이리스트는 멈춘 채로**(다시 틀려면 🎵 에서) |
| DJ 가 나갈 때 | 승계 규칙대로 다음 방장이 DJ(투게더룸 · 워킹룸 — 워킹룸 승계는 #475). **지금 곡은 끝까지** 틀고, 그다음부터 새 DJ 의 플레이리스트 |
| 다른 음악이 이길 때 | 방 안에서 마이홈 BGM ▶ · 내 플레이리스트 곡(파도타기 · 목록 · 명함)을 틀면 **그쪽이 이긴다**. 같이 듣기 창에 «다른 음악을 틀고 있어 같이 듣기가 멈췄어요 [다시 듣기]» — [다시 듣기] 는 DJ 의 지금 위치로 돌아온다 |
| 로비 카드 | 지금 곡 제목은 안 보임(«같이 듣기» 딱지 · «현재 DJ» 만 — #483 그대로) |
| DJ 표시 | DJ 머리 위 이름표에 «🎧 DJ» |

## 2. 데이터

### 2.1 `rooms/{방}/_meta.music` (이미 있음 — #479)
- 불. 방을 **열 때마다** 쓴다(2.4). 로비 사본은 `mu` 로 옮긴다(이미 됨).

### 2.2 `rooms/{방}/_music` (새 칸 — 구현 PR 1 에서 규칙)
```
rooms/{방}/_music = {
  id:     'jfKfPfyJRdk',        // 유튜브 videoId (11자 · 영숫자 _ -)
  title:  'lofi hip hop radio', // 1~100자 — 비면 listen-model 이 id 로 채운다 · 화면에는 글로만(textContent)
  by:     '<DJ 의 내 코드>',     // 쓴 사람 — 승계 뒤 «지금 곡은 옛 DJ 것» 을 가린다
  at:     1729500000000,        // 이 곡 0초 지점의 서버 시각(ms) — 재생 중 위치 = (서버 지금 − at) / 1000
  paused: false,
  pos:    0,                    // 멈췄을 때의 위치(초) — paused 일 때만 뜻이 있다
  seq:    7,                    // 바꿀 때마다 +1 — 규칙이 «지금보다 커야» 를 본다(늦게 온 옛 쓰기 거절)
  dur:    204                   // (있으면) 곡 길이(초) — DJ 재생 창 하트비트가 안다. 곡 끝 예비 판정에 쓴다
}
```
- **쓰는 때**: DJ 가 곡을 바꾸거나(다음 · 이전 · 곡 끝) 멈추거나 다시 틀 때만 한 번(수십 바이트). 재생 중 매초 쓰지 않는다.
- **읽는 때**: 같이 듣기 방(`_meta.music === true`) 안에 있는 동안만 이 칸 하나를 `onValue` 구독. 방을 나가면 끊는다. 멤버 구독(`orderByKey startAt('m')`)에는 실려 오지 않고, 인원 세기는 `_` 로 시작하는 칸을 거른다.
- **없음과 못 받음**: provider 는 첫 값이 오기 전 `undefined`(불러오는 중) · 칸 없음 `null`(틀 곡 없음 — DJ 플레이리스트가 비었거나 DJ 가 옛 앱) 을 가른다.
- **위치 계산**: 서버 시각은 `firebaseAPI.serverNow()`(`.info/serverTimeOffset` 보정 — 이미 하는 구독). provider 가 `now()` 로 내놓는다 — 방 서버 방은 여기서 서버 시각으로 바꾼다.

### 2.3 시크릿룸 설정 — 이 기기 `localStorage` `tw.secretRoomMusic`
- `'1'` 이면 주인이 시크릿룸을 열 때 `_meta.music = true`, 아니면 `false` 로 **늘** 쓴다(시크릿룸 `_meta` 는 비어도 남으니 지난 값이 살아 있지 않게).
- 계정에 매인 설정이라 `account.js` «신원을 놓을 때 이 기기에서 지우는 것» 목록에 넣는다.

### 2.4 방을 열 때 · 비울 때 — 지난 곡이 남지 않게
- `rooms/{방}` 은 통째로 지워지지 않는다(앱은 멤버 칸만 · 서버 함수는 빈 공용 방의 `_meta` · `_chatTab` 만 · 시크릿룸은 비어도 남김). 그래서:
  - **방을 여는 길**(만들기 `setRoomChannel` · 빈 방 선점 `claimEmptyRoom` · 시크릿룸 열기 · 되살리기)이 `_meta.music` 을 쓰면서 `_music` 을 **한 묶음으로**(`update` 다중 경로) 지우거나(일반 방) 첫 곡으로 새로 쓴다(같이 듣기 방).
  - **빈 방 청소**(`firebase/functions/room-stats.js` `sweepEmptyRooms`)가 빈 공용 방의 `_music` 도 걷는다 — 구현 PR 1.

## 3. 규칙 (`firebase/firebase-database-rules.json` — 구현 PR 1)
- `rooms/$room/_music`:
  - `.write`: 지우기는 늘 · 쓰기는 **쓰고 난 뒤** `_meta.music === true` 인 방에서만(일반 방 낙서를 막는다 · `newData.parent()` 로 보니 방을 열며 «켜기 + 첫 곡» 을 한 묶음으로 쓸 수 있고 «끄기 + 곡 쓰기» 묶음은 막힌다). 방장인지는 서버가 확인하지 못한다 — 화면에서 DJ 만 쓰게 막고, «DJ 만» 은 방 서버가 지킨다(`_meta` 와 같은 수준).
  - `.validate`: 필수 칸 `hasChildren(['id','title','by','at','paused','pos','seq'])` · `seq` 는 지금 값보다 커야 · `id` `^[A-Za-z0-9_-]{11}$` · `title` 1~100 · `by` 1~64 · `at` 숫자이고 서버 지금 + 60초 이하 · `paused` 불 · `pos` 0 이상 · `seq` 0 이상 10억 이하 정수(아주 큰 값으로 다음 쓰기를 막아 두지 못하게) · `dur`(있으면) 0 이상 · `$other` 거절.
- `.read`: `rooms/$room` 의 읽기를 그대로 받는다.
- 에뮬레이터 검사(`firebase/scripts/rules-emu-check.js`)에 모양 · 거절 경우(거절 이유가 차례 번호가 아니게 큰 번호로).

| `room/overhead.js` | DJ 이름표에 «🎧 DJ» 딱지 — 누가 DJ 인지는 `listen-model` 의 `djOf` 를 app.js 가 deps 로 넘긴다(직접 부르지 않음) |
| `apps/desktop/main.js` · `preload.js` | 재생 창 **세 번째 주인 `listen`**(지금은 마이홈 `home` · 상태칩 `playlist` — «나중에 연 쪽이 이긴다» 그대로). `listen` 일 때도 곡 끝 · 하트비트 신호를 넘기고, 받는 쪽은 같이 듣기 하나. **위치 옮기기** `companion:bgmSeek(초)`(주입 스크립트로 `video.currentTime` — 광고 중이면 아무것도 안 함) · **시작 위치로 열기** `openListenTrack(url, title, { start })`(유튜브 주소 `&t=초s`) · 하트비트 넷째 칸 **광고 중**(`hb:위치|길이|멈춤|광고` — playlist.js 는 0~2번만 읽어 옛 해석과 충돌 없음). 곡을 열기 전 늘 «한 곡 반복» 끔(`setBgmLoop(false)` — 개인 설정이 남아 있으면 곡 끝 신호가 안 온다). 새 바깥 주소 없음 |

- **재생 창 주인이 바뀌면**(`onBgmMode`): 같이 듣기가 지면 «다른 음악이 이김 [다시 듣기]» 화면으로 · 같이 듣기 구독은 그대로 둔다(다시 듣기 때 바로 위치를 안다).
- **멈춘 상태로 들어옴**: `_music.paused` 면 재생 창을 열지 않고 «멈춤» 화면만. 다시 틀면 `pos` 에서 연다(재생 창의 멈춤은 곡을 새로 열면 풀린다).
- **어긋남 맞추기**: 하트비트(5초)의 위치와 `posOf(_music)` 을 견준다. 5초 넘게 다르면 `bgmSeek`. 하트비트가 «광고 중» 이면 맞추지 않는다.
- **곡 끝**: 다음 곡을 쓰는 건 **지금 DJ 한 사람**(`djOf`)만. 신호는 DJ 재생 창의 «곡 끝» · 예비로 `posOf ≥ dur + 3초` · DJ 에게 재생 불가(`err`)면 넘김. 듣는 사람은 다음 `_music` 을 기다린다.
- **승계**: 새 DJ 앱은 `_music.by` 가 내가 아니면 «지금 곡은 끝까지» — 위 «곡 끝» 에서 내 플레이리스트 첫 곡을 쓴다. 옛 DJ 가 **멈춘 채** 나갔으면 새 DJ 가 바로 그 위치부터 다시 튼다. 내 플레이리스트가 비었으면 `_music` 을 지운다(«틀 곡 없음»).
- **시크릿룸에 주인이 없음**: `djOf` 가 없음 → 지금 곡이 끝나면(예비 판정 포함) 아무도 쓰지 않아 멈춘다 · 창은 «쉬는 중». 주인이 들어오면 주인 앱이 첫 곡을 쓴다.
- **소리**: 듣는 사람의 소리 크기 · 음소거는 이 기기에만(지금 BGM 소리 크기 저장과 같은 자리).
- **오류 번호**: `E-ROOM-05` 같이 듣기 곡을 못 바꿈(쓰기 실패 — DJ 에게만) · `E-ROOM-06` 곡을 못 틂(그 사람 재생 창 · 유튜브 재생 불가).

## 5. 서버 작업 필요 (`t-w-server` — 이 저장소 밖)
- 방 `meta` 에 `music` 을 받기(방 만들기 `join` 의 `create`) · 방 메시지 `music`(위 2.2 모양)을 **현재 방장만** 보낼 수 있게 · 들어오는 사람에게 지금 `music` 을 같이 준다 · `seq` 가 커지는 쓰기만 받는다.
- 서버 시각: 방 서버 방은 서버가 주는 시각으로 `at` 을 맞춘다(provider `now()`).
- 서버가 생기기 전 앱의 옛 길: Firebase `rooms/{방}/_music` · 방 서버 방에서는 같이 듣기 칸을 숨긴다(방 설정 줄과 같다). 서버가 생기면 바꿀 자리: `room/listen-provider.js`.

## 6. 옛 앱과 섞일 때
- 옛 앱(0.12 이하)은 `_music` 을 모른다 — 같이 듣기 방에 들어와도 음악이 안 나오고 자기 플레이리스트가 그대로 돈다.
- 옛 앱이 승계로 방장(= DJ)이 되면 아무도 곡을 쓰지 않아 지금 곡이 끝난 뒤 조용해진다(«틀 곡 없음»).
- 사용자 대부분이 0.13.0 으로 올라온 뒤 `config/minRoomVer` 를 올린다(로비 설계 6장과 같은 때).

## 9. 남은 위험
- 유튜브 광고 · 지역 제한 · 퍼가기 금지 곡은 사람마다 다르게 걸린다 — 그 사람만 소리가 안 나고(오류 번호), 방 전체는 그대로 간다.
- DJ 에게만 광고가 길게 붙으면 듣는 사람은 곡이 끝난 뒤 DJ 가 넘길 때까지 조용히 기다린다(`dur` 예비 판정이 DJ 쪽 늦음을 줄인다).
- 위치는 ±5초 안에서 맞춘다 — 같은 박자까지는 보장하지 않는다(말로 안내).
