원칙 · 하두리 감성 · 테마

책상 위 작은 3D 친구들과, 2000년대 초 한국 웹의 기억 — 하두리 · 싸이월드 미니홈피 · 스티커 사진 · 메신저 창. Together Working 의 화면은 그 시절의 반짝이는 창틀을 오늘의 바탕화면 위에 조용히 띄운다. 사용자는 하루 종일 다른 앱(그림·작업 툴) 위에 우리 앱을 켜 두므로, 귀엽되 방해하지 않는다가 모든 결정의 기준이다.

원칙 셋

  1. 레트로는 창 안에서, 오버레이는 조용히. 그라데이션 타이틀바·광택 버튼·스티커 장식은 사용자가 연 창 안에서 마음껏 쓴다. 늘 떠 있는 이름표·상태칩·토스트는 작고 납작하고 움직이지 않는다.
  2. 바탕은 우리 것이 아니다. 오버레이 위 글자는 흰 글자 + 검은 외곽선(plate-ink + plate-outline)처럼 어떤 바탕에서도 읽히는 조합만 쓴다. 테마 색을 오버레이 글자에 쓰지 않는다.
  3. 값은 토큰 하나에서. 색·글꼴·모서리를 규칙에 직접 박지 않는다. 테마가 바뀌면 같은 규칙이 값만 바꿔 받는다 — 앱이 이미 하고 있는 «베젤 세 색 접기» 방식 그대로다.

테마

  • 버블 · 낮(light, 기본): 2000년대 메신저. 연한 면 bg-face, 연두 그라데이션 타이틀바(title-a → title-b, 위에서 아래), 둥근 모서리(radius-sm 8 · radius-md 12), 광택 버튼.
  • 버블 · 밤(dark, 새로 추가): 같은 문법을 어둡게. 광택은 거의 끄고(흰 14% → 0), 그림자는 짙게. 밤 작업하는 그림쟁이를 위한 것 — 시스템 다크 모드를 따른다.
  • 클래식(classic): Win98. 회색 면, 남색 타이틀바(왼쪽 → 오른쪽), 모서리 0, 4방향 베젤(bevel-hi / bevel-lo / bevel-dark).
  • 색상 축(c1~c5: 그레이 · 스카이 · 그린 · 피치 · 민트 / 퍼플 · 블루 · 그린 · 노을 · 오로라)은 그대로 둔다. 이 시스템의 title-a · title-b · accent · bg-face · line · bg-select 가 각 축의 --acc-l · --acc-m · --acc-d · --acc-face · --acc-brd · --acc-tint 를 받는다. 표의 값은 기본 축(버블 c3 그린 · 클래식 c2 블루)이다.
  • 테마를 타지 않는 색: pop(배지), star, premium-*(유료 = 금색), sticker-*, plate-*, status-*, kakao, 토스트(tooltip-*).

색 쓰는 법

  • 본문 ink, 보조 ink-soft — bg-face · bg-face-2 · bg-field · bg-select 어디서나 4.5:1 이상(세 테마 모두 확인).
  • 강조를 글자로 쓸 땐 ink-accent, 면(바·점·켜진 토글)으로 쓸 땐 accent. accent 를 글자에 쓰지 않는다(낮 2.5:1).
  • 테두리: 장식은 line, 뜻이 있는 테두리(입력칸 · 세그먼트 · 토글 · 버튼)는 line-strong(3:1).
  • 상태는 색 + 낱말/모양 글자를 함께: 새 제보 ink-danger ●, 확인 중 ink-accent ◐, 고침 ink-ok ✓.
  • 위험 동작은 fill-danger + on-danger, 확인창 안에서만.
  • 포커스 고리는 focus 2px 실선, 1px 띄움.

글꼴

  • 본문 ui: 돋움 먼저(그 시절 메신저 글씨) → 맑은 고딕 → 애플 SD 산돌고딕 Neo. 맥에는 돋움·맑은 고딕이 없어 산돌고딕으로 떨어진다 — 정상이다.
  • 클래식 classic: Tahoma + 맑은 고딕. Tahoma 에는 한글이 없으니 한글 폰트를 반드시 같이 적는다(sim-font-hangul 이 본다).
  • 숫자 num: Consolas 계열. 레벨·카운터 숫자에만(작은 크기에서 3 과 8 이 갈린다).
  • 도트 pixel(제안): 갈무리(Galmuri11, OFL) → 둥근모 → 돋움. 스티커 문구·빈 화면 카오모지에만. 앱에 글꼴 파일을 넣기 전엔 돋움으로 떨어진다.
  • 크기는 일곱 단계만: micro 10 · caption 11 · body 12 · title-bar 12 굵게 · heading 14 · display 18 (+ 오버레이 nameplate 15). 9px 이하 금지, 10.5 · 11.5 같은 반 픽셀 금지.
  • 이 크기는 화면 배율 100% 기준이다. 전체 화면 크기(ui zoom, applyUiZoom)가 한꺼번에 키운다 — 개별 창에서 글자를 따로 키우지 않는다.

간격 · 모서리 · 그림자

  • 간격 space-1~space-7 = 2 · 4 · 6 · 8 · 12 · 16 · 24px. 창 안쪽 기본 space-4(8), 묶음 사이 space-5(12).
  • 모서리 radius-sm(버튼·입력·칩) · radius-md(창) · radius-pill(알약·경험치 바). 클래식은 모두 0. 폴더 탭은 위만, 탭 패널은 아래만 둥글다.
  • 그림자는 한 겹: 창 shadow-window, 버튼 shadow-button, 눌림 shadow-pressed, 쪽지 shadow-toast(각진 그림자 — 흐리게 바꾸지 않는다).
  • 누르는 것은 size-hit(24px) 이상. 상태칩 칸은 size-chip-btn(28×26).

움직임

  • 창 안: 120~180ms ease(펼침·토글·탭). 토스트 250ms 올라오기.
  • 오버레이: 페이드만(상태칩 접기 180ms). 상시 반복 애니메이션은 해금 보상(회차 별 빛 쓸기, 레벨 등급 배지)에만, prefers-reduced-motion 이면 멈춘다.
  • 전체 화면 캔버스 위엔 backdrop-filter, 큰 blur 그림자, 전체 덮는 반투명 막을 쓰지 않는다 — 3D 프레임(상한 60 · 유휴 30)을 깎는다.

아이콘

  • 앱 마크는 Logos 의 도트 아이콘(tw-mini.png, 28×26) — 16×15 로 줄여 image-rendering:pixelated. 다시 그리거나 부드럽게 만들지 않는다.
  • 버튼·탭·세그먼트 아이콘은 SVG 선 아이콘(14px, 선 1.6, currentColor). 이모지는 상태칩 칸 · 토스트 첫 글자 · 꾸미는 공간(마이홈·스티커)에서만. 자세한 기준은 «아이콘 · 글» 장.

ResizeGrip짧은 알약 · ⋮

창 크기를 바꾸는 손잡이 — 창 가장자리 가운데의 짧은 알약 + ⋮.

  • .tw-grip 10×28(size-grip), 세로 가장자리용. 가로 가장자리용은 .h(28×10, ⋮ 를 90° 돌림).

  • 모서리 대각선 손잡이(◢)는 쓰지 않는다 — 투명 오버레이 위에선 창 모서리와 바탕이 구분되지 않아 못 찾는다.
  • 히트 영역은 보이는 알약보다 사방 4px 넓게(::before 로). 커서 ew-resize / ns-resize.

알림

ConfirmDialog창 안 확인창 · confirm() 금지

되돌릴 수 없는 일 앞에서 한 번 묻는 창 안 확인창 — alert() · confirm() 대신.

  • 작은 창(260px) + 제목 질문(heading 14px) + 한 줄 설명 + 버튼 둘(오른쪽 정렬: 취소 · 실행).
  • 질문은 «~할까요?», 실행 버튼은 동사(«지우기»). «확인/취소» 쌍 금지.
  • 위험한 실행은 .tw-btn--danger, 아니면 --primary. 기본 포커스는 취소.
  • Esc = 취소, Enter = 포커스된 버튼. 바깥 반투명(rgba(0,0,0,.18))은 그 창 영역 안에만 — 화면 전체를 덮으면 사용자의 작업 앱 클릭이 막힌다.
  • role="alertdialog" + aria-labelledby.

왜: Electron 투명 창에서 confirm() 은 렌더러를 멈춘 채 대화상자가 안 보이는 함정이 있다(audit 검사 4). 그런데 지금도 app.js 에 confirm() 호출이 17곳 남아 있다 — 이행 2단계에서 이 컴포넌트로 바꾼다.

오버레이 원칙

앱은 화면 전체를 덮는 투명 · 항상 위 창이다. 우리 UI 위가 아니면 클릭이 뒤의 사용자 앱으로 빠진다(click-through). 사용자는 이 위에서 하루 종일 그림을 그리고 일한다.

1. 작게 · 가장자리에

  • 늘 보이는 조작부는 상태칩 묶음(StatusChip) 하나. 새 기능은 여기에 칸을 늘리기보다 «더보기 ▾» 안으로 넣는다.
  • 창은 열 때만 뜨고, 위치를 기억하며, 화면 가운데를 오래 차지하지 않는다.
  • 이름표 글자는 nameplate 15px 기본 — 더 키우는 건 사용자 설정으로만.

2. 어떤 바탕에서도 읽히게

  • 오버레이 글자 = plate-ink + plate-outline 8방향 외곽선. 흰 문서 · 검은 코드 편집기 · 사진 위 모두 통과해야 한다(Nameplate 미리보기의 세 바탕).
  • 오버레이 버튼은 불투명 bg-face 면 + 테두리 — 반투명 유리 버튼 금지(바탕이 비쳐 글자가 묻힌다).
  • 새 소식 점(pop)엔 1px 어두운 외곽을 둘러 흰 바탕에서도 보이게 한다.

3. 누를 자리는 분명하게 · 나머지는 통과

  • 누르는 것은 size-hit 24px 이상. 히트 영역은 UI_HIT_SEL 화이트리스트에 넣는다 — 안 넣으면 눌러도 클릭이 뒤로 뚫린다(audit 검사 2).
  • 장식(반짝이 · 후광 · 그림자 · 말풍선 꼬리)은 pointer-events:none.
  • 확인창의 어두운 막은 그 창 영역 안에만. 화면 전체를 막으면 사용자의 작업 앱이 멈춘 것처럼 느껴진다.

4. 움직이지 않기

  • 오버레이 요소는 상시 애니메이션이 없다. 예외는 해금 보상(회차 별 · 레벨 등급 배지)이며 prefers-reduced-motion 에서 멈춘다.
  • 알림은 소리 · 흔들기 대신 점 하나. 숫자 배지는 창 안에서만.
  • 토스트는 1.9초 · 한 번에 하나 · 마우스 통과.

5. 가볍게

  • 전체 화면 위 backdrop-filter · 큰 블러 그림자 · 전체 덮는 그라데이션 금지. 그림자는 한 겹, 블러 18px 이하.
  • 3D 캔버스는 프레임 상한 60 · 손 안 대면 30 으로 돈다 — UI 가 그 예산을 쓰지 않게, 오버레이 DOM 은 transform · opacity 로만 움직인다.

6. 숨길 수 있게 · 되돌릴 수 있게

  • «사무실 숨기기» 중에도 상태 칸 하나는 남는다 — 되돌릴 길이 사라지면 안 된다.
  • 창 위치 초기화(resetAllWinPositions)는 설정에 늘 둔다. 화면 밖으로 나간 창을 되찾는 유일한 길이다.

웹 관리자와 다른 점

  • 관리자(web-admin/src/app/styles/global.css)는 따뜻한 회백(--bg #f4f1ec) + 파랑 강조(--accent #2f5d8a) + 시스템 글꼴 14px 로, 앱과 다른 브랜드처럼 보인다.
  • 맞추는 정도: 관리자는 «약» 레트로 — 색 토큰 이름을 이 시스템과 같게(--ink · --ink-soft · --line · --ink-danger · --ink-ok · --ink-accent), 카드 머리에만 title-a → title-b 얇은 띠. 글자 크기는 관리자 14px 그대로(작업 화면이라 앱보다 크게 읽는다).
  • 관리자는 이미 prefers-color-scheme 밤 테마가 있다 — 앱 dark 값을 관리자 밤 값과 같은 뼈대로 만들었다.
  • 관리자 상태 칩(StatusChip.module.css)은 이 시스템 Chip 과 모양이 같다 — 넷의 색 이름만 맞춘다.

이행 순서

각 단계는 PR 하나 · 화면 차이 확인 후 다음으로. checks/ 에 검사를 붙인다.

  1. 토큰 다리 놓기 (화면 변화 0) — :root 에 --tw-* 를 옛 변수에 연결해 선언하고, html[data-theme="bubble"] · 클래식 블록에 같은 이름을 둔다. 하드코딩 Tahoma 121곳을 var(--tw-font-ui) 로(버블에서 돋움이 비로소 먹는다 — 유일한 «보이는» 변화). audit.py 에 «새 규칙은 #999 같은 손 회색 · 직접 font-family 금지» 검사를 더한다.
  2. 확인창 · 토스트 · 버튼 — ConfirmDialog 를 도메인 모듈(app/parts/ui-dialog.js, createDialog(deps))로 만들고 confirm() 17곳을 바꾼다. 버튼 계열을 .tw-btn 으로 묶어 버블 테마의 «광택 목록» · «radius 목록» 나열을 지운다. ink-soft 대비 수정이 여기서 들어간다.
  3. 창틀 · 탭 통일 — 인라인 타이틀바 그라데이션 49곳 · 탭 9종을 .tw-titlebar · .tw-tab 으로. 버블 테마의 창 · 타이틀바 ID 나열 블록이 사라진다 — 새 창이 테마를 빠뜨리는 사고가 구조적으로 없어진다.
  4. 글자 크기 정리 — 25가지를 7단계로. 반 픽셀(10.5 · 11.5)부터 가장 가까운 단계로. 설정창 탭을 5개 이하로 묶는다.
  5. 그리기 도구 세그먼트 · 크기 조절 손잡이 — _wdPic.tool 하나로 상태를 합치고 .tw-seg, 창 리사이즈를 .tw-grip 으로.
  6. 밤 테마 — 설정 › 화면 › 모양에 «버블 · 밤» 추가(시스템 따라가기 기본). 1~3단계가 끝나야 손 회색 · #fff 가 남지 않아 밤이 깨지지 않는다.
  7. 하두리 장식 — 도트 서체(갈무리, OFL) 파일을 app/assets/fonts/ 에 넣고(CSP font-src 'self' file: 안), 마이홈 · 스티커 사진 · 뽑기 결과에 Sticker 틀 · sticker-* 를 입힌다.
  8. 웹 관리자 맞추기 — 색 이름 통일, 카드 머리 띠.
