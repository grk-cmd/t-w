# /lesson — 리뷰 교훈 더하기

1. 먼저 묻는다: **이 지적을 기계가 늘 같은 답을 내는 검사(sim · lint · test)로 만들 수 있나?** 특정 함수 호출 · 경로 모양 · 상수 · 값(예: 서버에 쓰는 이름이 빈칸 · 자리 표시 값인가)처럼 입력 → 출력으로 판정되면 «된다».
   - 되고 작으면 → 지금 작업 브랜치에 검사를 만든다(`checks/sim-*` — CLAUDE.md «검사는 실제로 돌려서 판정한다» · «깨 보기» 포함, `CHECKS.md` §3 해시 같은 커밋). 줄 글은 더하지 않는다.
   - 되지만 지금 PR 에 못 넣으면(크다 · 다른 저장소) → 따로 할 일로 남긴다(GitHub 이슈 — 무엇을 검사할지 · 깨 볼 입력). `review-lessons.md` 에는 그 이슈를 가리키는 한 줄만 두고, 검사가 생기면 «검사로 옮김» 으로 바꾼다.
2. 검사로 못 만들 때만 한 줄로 줄인다: **무엇을 보면 → 왜 문제 → 어떻게 찾나**(grep 할 이름 · 경로 · 모양). 사연 · 날짜는 빼고, 이름 붙은 사고면 이름만(예: «말랑이 사고»).
3. `.claude/review-lessons.md` 의 맞는 절(데이터 · Firebase / 설계 / 동작 · 범위 — 없으면 새 절)에 더한다. 같은 뜻의 줄이 있으면 새로 쓰지 말고 그 줄을 다듬는다.
4. 지금 작업 브랜치에 커밋한다: `chore(harness): 리뷰 교훈 — <한 줄>`(검사면 `test(checks): …`). 작업과 섞이지 않게 커밋은 따로.
