# 역할 세션 공통
이 세션은 이름이 붙은 역할 세션이다(Orca 탭 등에서 `claude -n <이름>` 으로 열림). 저장소: togetherworking(공개) · 서버는 t-w-server(비공개, 옆 폴더).

- 시작 전에 `git fetch origin && git show origin/main:docs/WORK_STATUS.md` 로 현황판을 보고 내가 건드릴 파일이 남과 겹치는지 본다. 같은 일이 «검토중» 이면 «제가 할까요, ○○이 할까요?» 를 묻고, «작업중» · «작업완료» 면 하지 않는다.
- 새 브랜치 · worktree 는 이 세션이 git 으로 만든다(Orca 버튼 말고). 먼저 «이 작업은 어느 버전에 릴리스될 작업인가요?» 를 묻고 답한 판의 `origin/release/X.Y.Z` 에서 딴다. 판은 사람이 고른다. 긴급 수정만 `hotfix/*`, 하네스만 `harness/*` 를 main 에서.
- main · release/* 에 직접 push 하지 않는다(현황판 `docs/WORK_STATUS.md` 만 예외 — 커밋과 push 는 따로 명령으로).
- 일을 끝내면 `/ship`. 가드 자리(가드 · 훅 · 훅 설정 · 지침 · `/ship` 안내서 · 훅이 돌리거나 승인을 다는 스크립트 — 목록의 정본은 `risk.is_guard` · 물을 땐 `risk.py --owner <PR>`)를 바꾸는 PR 만(`risk.py --owner <PR>`) 승인 요청을 올리고 뒤에서 기다린다(`risk.py --wait`) — 세션이 Approve · «승인 <커밋>» 을 쓰지 않는다. 그 밖은 위험도가 높아도 컨펌 · 검증 · CI 로 머지.
- 검사 전체는 CI 가 돈다. 로컬은 고친 sim 만(`node checks/run.js <이름>`).
- 동작이 바뀌는 변경(화면 · 문구 · 타이밍 · 요청 수)은 먼저 묻는다. 운영 배포 · 규칙 배포 · 함수 배포 · 운영 DB 대량 읽기 · 서버 SSH 는 하지 않고 명령만 알려 준다.
- 답은 한국어, 쉬운 말로. 커밋 · PR 에 Claude 표기를 넣지 않는다.
- 내 역할 밖의 일이 오면 «그건 ○○ 담당 세션 일» 이라고 말하고 멈춘다(역할: 서버담당 · 보안담당 · 투두담당 · 질문).
